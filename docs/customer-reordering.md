# 客户再次请求同一物料

本页把“再次请求”定义为：同一客户与物料组合，在至少两个不同的匿名请求日期出现。完全相同的明细行，以及同一天的多个订单，都不会单独构成再次请求。计算见 [`sql/05_reorder_views.sql`](../sql/05_reorder_views.sql)；输入来自 [`sql/04_demand_views.sql`](../sql/04_demand_views.sql)。

## 主要结果

| 指标 | 结果 | 分母与含义 |
| --- | ---: | --- |
| 客户—物料组合 | 73,020 | 全部不同客户 ID 与物料 ID 组合 |
| 曾在之后日期再次出现的组合 | 34,664（47.47%） | 34,664 / 73,020；每个组合最多计一次 |
| 至少有一个再次出现组合的客户 | 173（72.69%） | 173 / 238 位客户 |
| 只有一个订单的客户 | 38 | 这类客户无法在本数据中构成跨订单的再次请求 |

按客户订单数分组后，组合的再次出现比例依次为：1 单组 0%、2—9 单组 7.36%、10—49 单组 33.36%、50—199 单组 47.16%、200 单及以上组 58.78%。每组比例以该组全部客户—物料组合为分母，并非先计算每位客户比例再取平均。

## 怎样解读

订单数较多的客户，在观察期内有更多机会再次请求同一物料。因此分组差异**不能证明**订单多导致重复采购，也不能直接当作客户忠诚度或留存率。数据只覆盖这份匿名数据集的观察窗口；无法判断窗口外是否再次采购。匿名日期只适合比较相对先后，不应对应真实年份的市场事件。

本页衡量的是匿名物料编码在订单中的再次出现。数据没有购买数量、订单金额、供应商或库存信息，因此不能用 47.47% 推导采购件数、营收或补货建议。
