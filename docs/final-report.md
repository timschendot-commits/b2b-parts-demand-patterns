# 项目结论：工业零部件需求与客户再次请求

## 业务问题与分析范围

这份作品集回答三个描述性问题：订单是否集中在少数客户？物料请求是否集中在少数编码？同一客户是否会在之后的匿名日期再次请求同一物料？分析覆盖 Zenodo B2B-Parts-Rec v1 的六份原始 CSV，共 285,941 条原始明细、24,532 个不同订单 ID、238 个客户 ID。客户和物料名称均已匿名化。

**分析单位必须分清。** 一条 CSV 行是原始明细，不等于一张订单，也不等于一件物料。订单数按不同 `ORDER_ID` 统计；物料出现次数按不同订单—物料组合统计；再次出现按同一客户—物料组合是否覆盖至少两个不同请求日期统计。完整定义见[指标字典](kpi-dictionary.md)。

## 主要发现

1. **客户订单集中。** 第一位客户关联 4,804 张不同订单，占 19.58%；前 10 位客户合计占 58.96%。这提示团队在取得客户价值和服务成本数据后，优先检查大客户依赖与服务连续性。现有数据不能将订单份额称为营收份额或利润贡献。
2. **物料请求分散。** 前 10 个物料仅占 221,886 个不同订单—物料组合的 2.52%。匿名物料编码很多，长尾管理值得进一步研究；但出现次数不能替代采购数量，也不能直接决定库存水平。
3. **重复请求存在，但各客户差异大。** 73,020 个客户—物料组合中，34,664 个至少在两个不同匿名日期出现，占 47.47%。这个合计比例受物料组合多的客户影响更大。逐客户计算后，238 位客户的比例中位数是 20.92%；至少 10 单的 134 位客户中位数是 40.37%。订单少的客户可观察到重复请求的机会更少，因此不能把两组差异解释为“订单数导致复购”。
4. **地区图只描述样本。** North America 有 5,189 个不同订单、7 位客户；Southern Europe 有 4,147 个不同订单、102 位客户。地区订单总数受样本客户构成影响，不能作为地区市场规模或扩张潜力排名。

## 可采取的下一步业务动作

| 优先级 | 适合做的事 | 在做决定前还缺什么 |
| --- | --- | --- |
| 1 | 与业务方核对前 10 位客户的服务连续性和需求波动 | 客户收入、毛利、合同与服务等级 |
| 2 | 对高频出现的匿名物料建立人工核查清单 | 可读物料名称、采购数量、库存、交期和关键性 |
| 3 | 在订单数相近且观察期相近的客户中复核再次请求模式 | 客户加入时间、真实需求场景与更长观察窗口 |

以上是**需要验证的工作方向**，不是从现有数据直接得出的采购或补货指令。尤其不能把 `PRICE_EXACT` 单价求和当作订单金额。

## 可靠性与局限

- 六份文件的大小和 MD5 与 Zenodo 记录一致；详细数据审计见[数据审计](data-audit.md)。
- 发现 44,781 条完全相同的额外明细行。由于没有数量和唯一明细 ID，保留原始行，并让核心指标依赖不同订单、不同日期或不同客户—物料组合；见[重复行核对](duplicate-audit.md)。
- Zenodo 简介中的“285,919 orders / 219 clients”与原始文件直接计数不同。作者预处理时剔除少于 3 行的客户后，恰好得到 285,919 **行**和 219 位客户；真正不同的订单 ID 是 24,532 个。本项目以原始文件及明确的 SQL 粒度为准。
- 日期经过匿名化平移。六个年份仅用于数据集内部排序与趋势图，不能与真实宏观事件或季节性政策联系。
- 数据没有采购数量、订单金额、货币、供应商、库存或交付日期，因此无法计算采购额、补货量、供应商绩效和库存周转。

报表、查询和核对脚本见[仓库首页](../README.md)；任何读者都可按[复现说明](reproduce.md)从 Zenodo 原始记录重新生成这些汇总数字。
